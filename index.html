1Главная идея MrrCode: как думать об игре 🐾

MrrCode — собственный игровой язык этого движка. Это не JavaScript и не Python. Главный файл проекта — main.mrr. Игра живёт внутри фиксированной логической сцены 800×450, а движок масштабирует её под экран устройства.

Почти любую игру удобно мыслить как четыре вещи:

  1. Состояние — переменные, в которых хранятся игрок, враги, счёт, здоровье, предметы, таймеры и т. п.
  2. Ввод — события pointerDown/Move/Up и состояние pointerX/Y, touchX/Y, touchCount.
  3. Обновление — update(dt): движение, физика, столкновения, правила игры.
  4. Рисование — те же кадры: rect, circle, sprite, text и другие функции рисуют текущее состояние.

Самая важная мысль: код не «двигает картинку». Код меняет состояние игры, а затем каждый кадр заново рисует его. Поэтому игрок может быть объектом, спрайтом или просто прямоугольником — механика от этого не меняется.

2Игровой цикл: start → ввод → update → рисунок

function start() {
    background("#101827");
    // начальные значения, загрузка состояния, подготовка игры
}

function update(dt) {
    // 1. изменить состояние
    // 2. проверить столкновения и правила
    // 3. нарисовать новый кадр
}

start() вызывается один раз после успешного запуска. update(dt) вызывается каждый кадр. dt — время между кадрами в секундах.

Важно: внутри function update(dt) dt — уже число. Пиши x += speed * dt, а не dt(). Вызов dt() допустим вне функции, когда имя dt не затенено локальным параметром.

Ввод-события можно объявить в main.mrr:

function pointerDown(x, y) {
    // один или несколько пальцев коснулись поля
}

function pointerMove(x, y) {
    // палец движется
}

function pointerUp(x, y) {
    // палец отпущен
}

Движок ориентирован на сенсорный ввод и мультитач. Клавиатурные и мышиные игровые функции не входят в документированный API.

3Синтаксис: переменные, значения, выражения

let score = 0;
let name = "Cat";
let alive = true;
let items = ["coin", "key"];
let player = {x: 100, y: 200, vx: 0, vy: 0};
const speed = 240;

Объявления — только let и const. Поддерживаются числа, строки, true, false, null, массивы и объекты. let используй для изменяемых значений, const — для постоянных.

Доступ к данным: items[0], player.x, player["x"]. Массивы и объекты можно менять напрямую.

Не используй методы через точку. Нельзя писать items.push(x), items.map(...), text.trim(), Math.floor(...) и другие вызовы obj.method(...). Вместо них используй встроенные функции MrrCode: push(items, x), trim(text), floor(x) и т. д.

Строгое равенство === и !== не поддерживается. Используй == и !=.

4Условия, циклы и функции

if (score >= 10) {
    print("Победа!");
} else {
    print("Продолжай");
}

for (let i = 0; i < 10; i++) {
    print(i);
}

for (let item of items) {
    print(item);
}

function damage(amount) {
    score -= amount;
    return score;
}

Есть if / else, while, два вида for, break, continue, пользовательские функции и return. Условное значение можно получить через тернарный оператор: let label = alive ? "Жив" : "Игра окончена";.

Операторы: + - * / % **; сравнения == != < > <= >=; логика ! && ||; присваивания = += -= *= /= %= **=; ++ --; унарные +x и -x.

Логические && и || работают с коротким замыканием, поэтому можно строить условия вроде alive && hp > 0.

5Координаты и геометрия — основа любой игры

Игровая сцена всегда 800×450. x растёт вправо, y — вниз. Точка (0,0) находится в левом верхнем углу.

ФормаКоординатыЧто означает
rectx,y,w,hлевый верхний угол + размер
circlex,y,rцентр + радиус
textx,yначальная точка текста

Размер окна устройства — другое понятие. screenWidth()/screenHeight() дают CSS-размер видимой области браузера. Для игрового мира используй gameWidth()/gameHeight(): они возвращают 800 и 450.

Практика: если нужно держать объект внутри экрана, ограничивай его логическими координатами:

player.x = clamp(player.x, 0, gameWidth() - player.w);
player.y = clamp(player.y, 0, gameHeight() - player.h);

6Состояние игры: игрок, враги, предметы и списки

Храни игровую модель в переменных. Для одного персонажа достаточно объекта:

let player = {x: 100, y: 300, w: 48, h: 48, vx: 0, vy: 0, hp: 3};

Для множества однотипных объектов используй массив:

let coins = [
    {x: 150, y: 200, w: 24, h: 24},
    {x: 350, y: 160, w: 24, h: 24}
];

for (let coin of coins) {
    circle(coin.x + 12, coin.y + 12, 12, "#ffd166");
}

Для добавления и удаления элементов используй push, pop, splice, shift, unshift. Для поиска — indexOf и contains. Для длины — length.

7Ввод: тап, удержание и мультитач

Есть два основных подхода:

  • Событие — когда важен сам факт действия: pointerDown(x,y), например прыжок или нажатие кнопки.
  • Состояние — когда действие продолжается, пока палец держит экран: pointerDownNow(), pointerX(), pointerY().
function pointerDown(x, y) {
    if (x > 600) {
        player.vx = 240;
    }
}

function update(dt) {
    if (pointerDownNow()) {
        player.x = lerp(player.x, pointerX() - player.w / 2, 0.15);
    }
}

Мультитач: touchCount() сообщает количество пальцев, а touchX(i)/touchY(i) — координаты пальца с индексом i. Поэтому можно сделать управление «лево + прыжок» двумя пальцами одновременно.

let dir = 0;
let i = 0;
while (i < touchCount()) {
    let x = touchX(i);
    if (x < 270) dir = -1;
    if (x > 530) dir = 1;
    i += 1;
}

8Рисование: кадр за кадром

background("#101827");

function update(dt) {
    rect(40, 60, 100, 60, "#ff8844");
    circle(260, 100, 30, "#70d6ff");
    line(20, 200, 400, 250, "#ffffff", 2);
    text("Счёт: " + score, 20, 20, "#ffffff", 20);
}

В начале кадра движок очищает игровое поле. Поэтому «постоянный» рисунок не сохраняется сам: его нужно нарисовать снова в следующем update. Для постоянного фона используй background(color). clear(color) закрашивает текущий кадр.

Для следов, рисования пальцем и частиц сохраняй точки/частицы в массиве и перерисовывай их каждый кадр.

9Спрайты и анимация

Импортируй PNG во вкладке «Файлы». Имя ресурса — имя файла без расширения, например hero.png → sprite("hero", ...).

sprite("hero", player.x, player.y, 64, 64);

Если размеры не указаны, используется исходный размер PNG. Если ресурса нет, движок показывает placeholder и пишет предупреждение в консоль.

Для sprite sheet используй spriteAnim. frameW и frameH — размеры одного кадра в исходном PNG, а fps — скорость анимации.

spriteAnim("hero", 320, 150, 128, 128, 32, 32, 8);

10Столкновения: overlapRect

overlapRect проверяет пересечение двух осевых прямоугольников. Важно: если прямоугольники только соприкасаются краями, это не считается столкновением.

if (overlapRect(
    player.x, player.y, player.w, player.h,
    coin.x, coin.y, coin.w, coin.h
)) {
    score += 1;
}

Это базовый строительный блок для монет, пуль, врагов, стен и предметов. Для круга или сложной формы обычно удобно иметь простой невидимый прямоугольник-«хитбокс».

Пример удаления собранной монеты:

let i = length(coins) - 1;
while (i >= 0) {
    let c = coins[i];
    if (overlapRect(player.x, player.y, player.w, player.h, c.x, c.y, c.w, c.h)) {
        splice(coins, i, 1);
        score += 1;
    }
    i -= 1;
}

Удалять элементы при проходе массива с конца удобно: индексы уже обработанных элементов не сдвигаются.

11Физика: скорость, гравитация и moveBody

Простая физическая модель хранит позицию и скорость: x, y, vx, vy. moveBody(body, dt, gravity) сначала меняет вертикальную скорость по гравитации, затем перемещает объект.

let ball = {x: 100, y: 100, vx: 180, vy: 0};

function update(dt) {
    moveBody(ball, dt, 600);
    circle(ball.x, ball.y, 16, "#ffd166");
}

Вызов ограничивает используемый dt диапазоном 0..0.1 секунды. Это полезная защита от слишком большого скачка физики.

Отскок от пола можно сделать вручную через столкновение:

if (ball.y > 400) {
    ball.y = 400;
    ball.vy = -abs(ball.vy) * 0.7;
}

12Камера и большие миры

camera(x,y) сдвигает последующее рисование. Координаты объектов и касаний при этом не меняются. Поэтому мир можно хранить в координатах больше 800×450.

function update(dt) {
    clear("#101827");

    camera(player.x - 300, 0);

    rect(0, 380, 2000, 70, "#2a3a55");
    sprite("hero", player.x, player.y, 64, 64);

    camera(0, 0);
    text("Счёт: " + score, 20, 20, "#ffffff", 20);
}

После рисования мира верни camera(0,0), если дальше рисуешь интерфейс, чтобы HUD не двигался вместе с миром.

Важно: камера влияет на функции рисования, но не переводит координаты pointerX()/pointerY(). Если игрок касается экрана, тебе самому нужно сопоставить экранную координату с мировой, например добавить смещение камеры.

13Объекты вкладки «Сцена»

Сцена — отдельный визуальный слой редактора. Можно создать прямоугольник, круг или текст, дать ему уникальное имя и получить его из кода через object("name").

let hero = object("hero");

function update(dt) {
    if (hero != null && pointerDownNow()) {
        hero.x = pointerX() - hero.w / 2;
        hero.y = pointerY() - hero.h / 2;
    }
}

У прямоугольника доступны x,y,w,h,color; у круга — x,y,r,color; у текста — x,y,text,size,color. Координаты прямоугольника — левый верхний угол, координаты круга — центр.

Два независимых подхода: сценой можно управлять из кода, либо рисовать всё непосредственно функциями. Перетаскивание объекта в редакторе не переписывает произвольные вызовы rect() в исходном коде.

14Модули: как разделить большую игру на файлы

Когда игра растёт, вынеси системы в отдельные .mrr-файлы. Например, player.mrr может хранить движение игрока, а main.mrr — главный цикл.

// player.mrr
let px = 100;

function resetPlayer() {
    px = 100;
}

function getPlayerX() {
    return px;
}
// main.mrr
from "player" import resetPlayer, getPlayerX;

function start() {
    resetPlayer();
}

function update(dt) {
    rect(getPlayerX(), 200, 48, 48, "#3ddc84");
}

Поддерживаются обычный импорт, несколько имён, import * и псевдоним через as. Расширение .mrr можно не писать. Модуль выполняется один раз при первом импорте и затем кэшируется. Циклические импорты запрещены.

Точка входа всегда main.mrr. Обработчики игры должны быть объявлены там или импортированы туда.

16Математика, случайность и плавность

Основные функции: abs, sqrt, sin, cos, atan2, pow, min, max, clamp, floor, ceil, round, sign, lerp, map.

// плавно ведём объект к цели
player.x = lerp(player.x, targetX, 0.1);

// случайная позиция
let x = randomInt(40, 760);
let y = rand(80, 400);

// расстояние между двумя точками
let dx = targetX - player.x;
let dy = targetY - player.y;
let distance = sqrt(dx * dx + dy * dy);

sin, cos и atan2 используют радианы. Для угла, который постоянно увеличивается, обычно удобно делать angle += speed * dt.

17Время, счётчики и логика «раз в несколько секунд»

time() — секунды с момента запуска игры. Для логики, зависящей от кадров, используй dt.

let spawnTimer = 0;

function update(dt) {
    spawnTimer += dt;
    if (spawnTimer >= 2) {
        spawnTimer = 0;
        // создать нового врага
    }
}

Такой таймер не зависит от того, сколько кадров в секунду рисует устройство. То же правило подходит для движения: x += speed * dt, а не просто x += speed.

18Сохранения и звук

let best = load("bestScore", 0);

function finishGame() {
    if (score > best) {
        best = score;
        save("bestScore", best);
    }
    playTone(660, 0.15, 0.08);
}

save(key,value) сохраняет JSON-совместимое значение в локальном хранилище браузера. load(key,defaultValue) возвращает сохранённое значение или значение по умолчанию.

playTone(frequency,duration,volume?) создаёт короткий синтезированный тон. Громкость ограничивается движком. stopSound() приостанавливает аудиоконтекст. На некоторых браузерах звук надёжнее запускать после действия пользователя.

19Состояния игры: меню, игра, пауза, победа

Для небольших игр достаточно одной переменной состояния:

let state = "menu";

function pointerDown(x, y) {
    if (state == "menu") state = "playing";
    else if (state == "playing" && score >= 10) state = "win";
}

function update(dt) {
    clear("#101827");

    if (state == "menu") {
        text("ТАП — НАЧАТЬ", 280, 210, "#ffffff", 24);
    } else if (state == "playing") {
        // игровая логика
    } else {
        text("ПОБЕДА!", 330, 210, "#ffd166", 30);
    }
}

Это простой способ не смешивать меню и игровую механику. Для большой игры можно хранить дополнительные флаги и таймеры, но принцип тот же: сначала состояние, затем правила этого состояния, затем рисунок.

20Как сделать нормальную игру: универсальный каркас

Ниже — хороший шаблон для большинства небольших 2D-игр: состояние игрока → ввод → движение → границы → столкновения → создание/удаление объектов → UI.

let player = {x:80, y:300, w:48, h:48, vx:0, vy:0};
let coins = [];
let score = 0;
let gameState = "playing";

function start() {
    background("#101827");
    push(coins, {x:300, y:280, w:24, h:24});
    push(coins, {x:500, y:180, w:24, h:24});
}

function pointerDown(x, y) {
    if (x < 260) player.vx = -240;
    else if (x > 540) player.vx = 240;
    else player.vy = -420;
}

function update(dt) {
    moveBody(player, dt, 900);

    player.x = clamp(player.x, 0, gameWidth() - player.w);

    let i = length(coins) - 1;
    while (i >= 0) {
        let c = coins[i];
        if (overlapRect(player.x, player.y, player.w, player.h, c.x, c.y, c.w, c.h)) {
            splice(coins, i, 1);
            score += 1;
            playTone(880, 0.08, 0.06);
        }
        i -= 1;
    }

    clear("#101827");
    rect(0, 390, 800, 60, "#263650");
    rect(player.x, player.y, player.w, player.h, "#70d6ff");

    for (let c of coins) {
        circle(c.x + 12, c.y + 12, 12, "#ffd166");
    }

    text("Счёт: " + score, 20, 20, "#ffffff", 22);
}

Это не «движок внутри движка», а образ мышления. Меняй механику, графику и структуру данных, сохраняя последовательность: ввод → состояние → правила → столкновения → рисование → UI.

21Архитектура больших проектов

Когда проект становится сложнее, разделяй ответственность. Например:

  • main.mrr — точка входа, состояние игры и главный цикл;
  • player.mrr — состояние и движение игрока;
  • enemies.mrr — создание и поведение врагов;
  • levels.mrr — данные уровня;
  • ui.mrr — функции отрисовки интерфейса.

Модули должны обмениваться небольшими понятными функциями. Не делай один гигантский файл, если несколько систем можно разделить. При этом помни: экспортируемыми становятся объявленные в модуле функции и переменные, которые импортируются в main.mrr.

23Датчики телефона

orientationAngle() даёт угол ориентации экрана, isPortrait() — вертикально ли окно. tiltX(), tiltY(), tiltZ() возвращают углы ориентации устройства.

function pointerDown(x, y) {
    requestMotion();
}

function update(dt) {
    let x = clamp(gameWidth() / 2 + tiltX() * 3, 20, gameWidth() - 20);
    circle(x, 220, 20, "#70d6ff");
}

На некоторых устройствах браузер требует разрешение. Поэтому requestMotion() лучше вызывать в ответ на пользовательское касание. Без поддержки или разрешения значения наклона могут оставаться нулевыми.

25Чего MrrCode не умеет

  • var не поддерживается.
  • === и !== не поддерживаются.
  • Вызовы методов через точку вроде array.map() или text.trim() запрещены.
  • Произвольный DOM, fetch и произвольные JavaScript API не являются API игры.
  • Клавиатурные функции не являются документированным способом управления игрой.
  • Автоматической синхронизации изменений вкладки «Сцена» с исходным кодом нет.
  • Сцена и код — разные рабочие процессы; преобразование сцены в код выполняется отдельной командой.

Это важнее, чем похожесть синтаксиса на JavaScript: знакомая конструкция не становится поддерживаемой только потому, что она существует в другом языке.

26Отладка: как быстро найти ошибку

  1. Запусти игру. Если есть синтаксическая ошибка, смотри первую ошибку в консоли.
  2. Проверь имя. Файл, функция, спрайт и объект сцены должны называться именно так, как написано в коде.
  3. Проверь тип данных. Например, moveBody требует объект с x,y,vx,vy.
  4. Проверь координаты. Помни про 800×450 и про разницу между центром круга и углом прямоугольника.
  5. Проверь dt. В update(dt) используй число dt, не dt().
  6. Поставь print. Выведи значения прямо перед подозрительным условием.
  7. Включи Debug. Точки останова помогают остановить выполнение на выбранной строке.
print("player", player.x, player.y, player.vx, player.vy);
print("touch", pointerX(), pointerY(), touchCount());

Валидатор помогает найти часть проблем заранее, но только реальный запуск показывает, правильно ли работает игровая логика.

27Правильный рабочий процесс от идеи до готовой игры

  1. Сформулируй механику: кто игрок, что он делает, как побеждает и проигрывает.
  2. Сделай прототип без графики: прямоугольники и круги вместо спрайтов.
  3. Добавь управление: сначала один понятный способ касания, затем мультитач при необходимости.
  4. Добавь движение через dt: скорость в единицах в секунду, а не «пикселей за кадр».
  5. Добавь столкновения: overlapRect и простые хитбоксы.
  6. Добавь состояние: меню, игра, пауза, победа/поражение, счёт, здоровье.
  7. Замени прототипную графику: импортируй PNG и используй sprite/spriteAnim.
  8. Раздели код: когда файл растёт, вынеси системы в модули.
  9. Добавь звук и сохранения: playTone, save/load.
  10. Проверь игру на устройстве: касания, ориентацию, полноэкранный режим и ресурсы.
  11. Экспортируй проект: не полагайся только на локальный автосейв.

Золотое правило: сначала механика, потом графика. Если игра работает на простых фигурах, заменить их на красивые PNG намного проще, чем отлаживать механику одновременно с графикой.

30ИИ-агент: как получать хороший код

ИИ получает контекст проекта и может создавать/изменять .mrr-файлы, работать со сценой и сообщать, какие PNG нужно импортировать. Изображения сам агент не генерирует.

Хороший запрос описывает жанр + управление + механику + условия победы/поражения + ограничения по изменяемым файлам. Например: «Сделай раннер на 800×450: персонаж автоматически бежит, тап прыгает, монеты дают очки, столкновение с препятствием заканчивает игру. Используй только касания, не меняй имя спрайта hero».

После применения результата всегда запускай игру и смотри консоль. Не считай код правильным только потому, что он выглядит правдоподобно: MrrCode имеет собственную грамматику и собственный API.

Приватность: API-ключ хранится локально в браузере и отправляется выбранному провайдеру. Не помещай в запросы пароли и другие секреты.

31Сохранение, экспорт и публикация

  • ⬇ .mrr сохраняет только выбранный исходный файл.
  • ⬇ Проект — резервная копия проекта с исходниками, ресурсами и сценой.
  • 💾 / Автосейв — локальная копия в текущем браузере.
  • 🕘 Версии — локальная история снимков проекта.
  • 🎮 Сборка HTML — отдельный HTML запускаемой игры.

Локальное сохранение не является полноценной резервной копией и не обязано переноситься на другое устройство. Перед крупным изменением экспортируй проект.

При публикации через GitHub Pages помни: опубликованный HTML доступен посетителям. Секретные API-ключи нельзя встраивать в клиентский код — всё, что попало в HTML, можно прочитать.

32Ограничения, которые нужно помнить всегда

  • Логическая сцена: 800×450.
  • Ввод игры: касания и мультитач.
  • update(dt): dt — секунды; внутри update не вызывай dt().
  • moveBody: объект должен иметь x,y,vx,vy.
  • overlapRect: только строгое пересечение, касание границ не считается.
  • camera: сдвигает рисование, но не координаты ввода.
  • spriteAnim: нужны импортированный PNG и размеры кадра в исходных пикселях.
  • Модули: выполняются один раз и кэшируются; циклические импорты запрещены.
  • Не вызывай JavaScript-методы через точку и не придумывай функции, которых нет в API.
  • Лимит операций защищает от зависания, но бесконечные/очень тяжёлые вычисления всё равно делать не следует.

Эта страница описывает фактическую модель движка и его документированный API. Если функция не описана здесь или в шпаргалке, сначала проверь встроенный справочник, а не предполагай её наличие по аналогии с другим языком.

34Куда идти дальше

После изучения этой страницы не нужно запоминать каждую функцию дословно. Запомни карту движка: 800×450 → main.mrr → start/update → касания → состояние → dt → рисование → overlapRect/moveBody → спрайты → модули → save/load → отладка.

Для конкретной функции используй «📖 Шпаргалку», но механику игры строй из принципов выше. Тогда новые функции становятся инструментами, а не набором магических команд.
