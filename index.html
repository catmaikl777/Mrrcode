1Как устроен проект 🐾

Игра — запущенный на весь экран устройства экран. Код — логика на MrrCode. Сцена — прямоугольники, круги и текстовые объекты. Файлы — код и PNG-спрайты. 🤖 ИИ — агент, который пишет код за тебя. Точка входа — main.mrr. Координаты игровой сцены всегда 800×450 — движок масштабирует её под экран. Для размера окна используй screenWidth()/screenHeight(), для логических координат — gameWidth()/gameHeight().

2Переменные и типы 🐾

let health = 100;
let title = "Моя игра";
let alive = true;
let inventory = ["ключ", "зелье"];
let stats = {speed: 120, score: 0};
const maxHealth = 100;

Используй let для изменяемого значения и const для постоянного. Поддерживаются числа, строки, boolean, null, массивы и объекты.

3Условия, циклы и функции 🐾

if (health <= 0) {

let i = 0;
while (i < 5) { i += 1; }

for (let n = 0; n < 3; n++) { print(n); }

Операторы: + - * / % **, сравнения == != < > <= >=, логические && || !, присваивания = += -= *= /= %=, инкремент ++ --. Вставлять их удобно кнопками на панели над редактором.

4Игровые события и управление касаниями 🐾

function start() {
    // один раз при старте
}
function update(dt) {
    // каждый кадр; dt — секунды с прошлого кадра
}
function pointerDown(x, y) { print("Палец коснулся", x, y); }
function pointerMove(x, y) { // палец движется по полю }
function pointerUp(x, y)   { // палец отпущен }

Состояние касаний прямо в update:

pointerX()        // X последнего касания (0..800)
pointerY()        // Y последнего касания (0..450)
pointerDownNow()  // true, пока палец держит поле
touchCount()      // сколько пальцев сейчас на поле
touchX(i)         // X i-го пальца (0 … touchCount()-1)
touchY(i)         // Y i-го пальца

Мультитач — кружок под каждым пальцем:

function update(dt) {
    clear("#101827");
    let i = 0;
    while (i < touchCount()) {
        circle(touchX(i), touchY(i), 30, "#70d6ff");
        i += 1;
    }
}

Клавиатуры и мыши в движке нет — только касания. Типичная схема: зоны экрана (левая треть — влево, правая — вправо, тап в центре — прыжок).

5Рисование

clear("#101827");
rect(20, 30, 120, 60, "#ff8844");
circle(220, 100, 30, "#70d6ff");
line(10, 10, 300, 200, "#ffffff", 2);
text("Привет!", 20, 140, "#ffffff", 20);

Движок сам очищает экран в начале каждого кадра — старая графика не наслаивается. Вызови background(color) один раз в start(), чтобы задать постоянный фон. clear(color) меняет заливку только текущего кадра; если вызывать его в каждом update, он будет перекрашивать каждый кадр и перекроет заданный фон. Для «следа» от пальца копи точки в массив и перерисовывай их каждый кадр.

Для прокрутки мира используй camera(x,y); она сдвигает рисование, но не координаты касаний. Для столкновений прямоугольников есть overlapRect(...), а moveBody(body,dt,gravity) обновляет объект с полями x,y,vx,vy. Анимированный спрайт-лист рисуется через spriteAnim(...).

6Объекты вкладки «Сцена»

Выбери объект и задай уникальное имя name, например hero:

let hero = object("hero");

function update(dt) {
    if (pointerDownNow()) {
        hero.x = pointerX() - 32;   // объект идёт за пальцем
        hero.y = pointerY() - 32;
    }
}

Прямоугольник: x, y, w, h, color; круг: x, y, r, color; текст: x, y, text, size, color. Объекты сцены рисуются поверх игрового кадра. Сцену может создавать и ИИ-агент.

7PNG-спрайты

Открой «Файлы» → «Импорт PNG-спрайта» и используй имя ресурса в sprite(name, x, y, width, height):

function update(dt) {
    clear("#182235");
    sprite("heroSprite", 100, 120, 64, 64);
}

Имя спрайта — имя файла без расширения. Повторный импорт того же файла заменяет спрайт. Если игру делает ИИ, он напишет в чат список изображений, которые нужно импортировать, и их имена.

8Импорт из других файлов (модули)

Создай player.mrr («Файлы» → «Новый .mrr»):

// файл player.mrr
function spawnPlayer() {
    print("Игрок появился!");
}

В main.mrr импортируй имена:

from "player" import spawnPlayer;
from "player" import spawnPlayer, movePlayer;
from "player" import spawnPlayer as spawn;
from "player" import *;

function start() {
    spawnPlayer();
}

«Запуск» всегда выполняет main.mrr. Имя файла можно писать без .mrr и без кавычек. Код модуля выполняется один раз при первом импорте; циклические импорты запрещены. События (update, pointerDown…) должны быть в main.mrr или импортированы в него.

10Редактор на сенсоре, сохранение и ограничения


Всё делается пальцем: панель над редактором вставляет скобки, операторы, шаблоны и функции; пока печатаешь имя — всплывает список дополнений (тапни вариант); после from " подсказываются файлы, после import — функции из файла, после object(" и sprite(" — имена сцены и спрайтов. «📖 Шпаргалка» — поиск по функциям с кнопкой «Вставить».


Используй «⬇ .mrr» для кода и «⬇ Проект» для пакета исходников и ресурсов. Данные хранятся в памяти страницы — экспортируй проект, чтобы не потерять. MrrCode — ограниченный собственный язык, а не полный JavaScript. Выполнение имеет лимит операций для защиты от зависания.






11Визуальный выбор цвета


В редакторе кода можно менять HEX-цвета без ручного ввода. Установи курсор внутри значения вида #70d6ff и нажми 🎨 Цвет. Выбери нужный оттенок — редактор заменит HEX-код прямо в текущем месте.


Поддерживаются цвета #RGB, #RGBA, #RRGGBB и #RRGGBBAA. Также можно дважды тапнуть по HEX-цвету в коде, чтобы открыть выбор цвета.

12ИИ-агент


Кнопка «🤖 ИИ» в шапке открывает агента. Подключение — на тебе:


1. Нажми «⚙ Подключение».

        2. Base URL — адрес OpenAI-совместимого API без завершающего /chat/completions (например https://api.openai.com/v1, OpenRouter, Together, локальный LM Studio и т.п.).

        3. API-ключ и имя модели (например gpt-4o-mini).

        4. «💾 Сохранить» — ключ хранится только в твоём браузере (localStorage), запросы идут напрямую провайдеру.


Напиши задачу, например: «Сделай игру: зелёный квадрат бегает за пальцем и собирает жёлтые монеты, со счётом». ИИ получит контекст проекта: код всех файлов, список спрайтов и сцену. Он может:


• создавать и перезаписывать файлы кода (.mrr), включая модули с импортами;

        • работать со сценой как агент — создавать/заменять объекты (прямоугольники, круги, текст);

        • сообщать, какие изображения нужно импортировать (имя PNG + описание) — картинки ИИ не генерирует, их импортируешь ты во вкладке «Файлы».


Все изменения применяются сразу и помечаются в чате тегами. Провайдер должен разрешать запросы из браузера (CORS); при ошибке сообщение появится в чате.






13Актуальная документация для ИИ


ИИ получает встроенную спецификацию MrrCode 0.2.0 перед запросом. Она содержит расширение .mrr, ключевые слова и встроенные команды.


ИИ также должен учитывать текущий код проекта: пользовательские переменные, функции и параметры извлекаются из текущего файла и используются как контекст.




14Шпаргалка по синтаксису языка


Переменные и значения: let score = 0;, const speed = 120;; числа, строки в кавычках, true, false, null, массивы [10, 20] и объекты {x: 10, y: 20}.


Массивы и свойства: items[0] читает первый элемент; items[1] = 42 меняет элемент. У строк и массивов есть свойство length. У объекта доступны поля через player.x или player["x"]. Не вызывай методы JavaScript через точку — стандартные операции записываются функциями, например push(items, value), slice(items, 0, 2).


Операторы: арифметика + - * / % **; сравнения == != < > <= >=; логика ! && ||; присваивания = += -= *= /= %= **=; увеличение/уменьшение ++ --; выбор значения условие ? значение1 : значение2.


Условия и циклы: if (условие) { ... } else { ... }, while (условие) { ... }, счётчик for (let i = 0; i < 10; i++) { ... }, перебор for (let item of items) { ... }. В циклах поддерживаются break и continue.


Функции и шаблонные строки: function double(n) { return n * 2; }; вызов — double(4). В шаблонной строке обратные кавычки позволяют вставлять выражение: `Score: ${score}`.


Строковые функции: trim, upper, lower, startsWith, endsWith, replace, contains, split, join. Для массивов: push, pop, splice, shift, unshift, indexOf, slice, length. Также доступны toString, toNumber, typeof, математические функции, сохранения save/load и синтезированный звук playTone/stopSound. Ищи любую функцию в «📖 Шпаргалке» или начинай печатать имя в редакторе.

16Вкладка «Игра»: запуск, экран и консоль


▶ Запуск выполняет main.mrr. ■ Стоп останавливает игровой цикл. Если полноэкранный режим недоступен в текущем браузере или WebView, игра может остаться в обычном окне — это ограничение среды, а не обязательно ошибка кода.


⛶ Во весь экран просит браузер расширить игровую область; браузер может потребовать запуск по нажатию пользователя. В полноэкранном режиме есть кнопки остановки и выхода.


Консоль показывает системные сообщения, предупреждения, ошибки и вывод print(...). «Очистить» удаляет видимые записи, но не исправляет причину ошибки. Смотри первую ошибку после запуска: последующие сообщения иногда являются её следствием.


В движке управление игрой ориентировано на касания и мультитач. Для мобильного управления используй зоны холста или координаты pointerX(), pointerY(), touchX(i), touchY(i). Обычные события клавиатуры и мыши не являются документированным игровым API.

    2. 

  2. Выбери его в списке или коснись объекта на холсте. После выбора открываются его свойства.
    3. 

  3. Перетаскивай объект по холсту. Если включён режим изменения размера, потяни угловой маркер.
    4. 

  4. Сетка показывает направляющие; Привязка включает шаг привязки 10 пикселей; Размер включает/выключает изменение размера.
    5.

⬇ Сцена экспортирует данные сцены, ⬆ Сцена загружает сцену из файла, Очистить удаляет объекты сцены, а ⌘ В код генерирует MrrCode на основе объектов. Преобразование сцены в код — отдельная операция: произвольные команды rect() из исходника автоматически не превращаются в редактируемые объекты сцены.

19Вкладка «Файлы»: исходники, ресурсы и перенос проекта


Новый .mrr создаёт файл исходного кода. main.mrr — точка входа; дополнительные файлы подключаются оператором from "имя" import функция;. После создания файла открой его и объяви в нём функции, которые импортируются в главный модуль.


Импорт PNG-спрайта добавляет изображение в ресурсы проекта. Имя ресурса — имя файла без расширения; например hero.png используется как sprite("hero", x, y, w, h). Если PNG является листом кадров, используй spriteAnim(...) и размеры одного кадра в исходном изображении.


⬇ Проект / ⬆ Проект экспортируют и импортируют пакет проекта, в котором могут храниться исходники, спрайты и сцена. Используй этот вариант для резервной копии или переноса проекта; экспорт одного .mrr сохраняет только код выбранного файла.


💾 Автосейв сохраняет проект локально в этом браузере. Локальное сохранение не является резервной копией и не переносится автоматически на другое устройство или в другой браузер. Для надёжности периодически экспортируй проект в файл.


🕘 Версии открывает историю снимков проекта: можно выбрать сохранённую версию и восстановить её. История хранится локально и ограничена количеством снимков, поэтому экспорт проекта остаётся важным.


🔎 Проверить ресурсы ищет буквальные ссылки на спрайты и объекты сцены, для которых нет соответствующего ресурса. Проверка не может гарантированно обнаружить имена, которые формируются динамически во время выполнения.


🎮 Сборка HTML создаёт отдельный HTML-файл игры. Это экспорт запускаемой игры, а не редактора MrrCode Studio: интерфейс вкладок, редактор и инструменты проекта в итоговый файл не входят. Проверь готовую сборку отдельно после экспорта.






20Отладка и диагностика ошибок


Включи 🐞 Debug в редакторе. В панели отладки можно указать номер строки и добавить точку останова; список показывает активные точки. «Очистить точки» убирает все установленные точки. Точка останова помогает остановить выполнение на выбранной строке, но не объясняет автоматически, как исправить логику.


Рекомендуемый порядок поиска проблемы:


    

  1. Останови игру и запусти её снова, чтобы получить свежие сообщения.
    2. 

  2. Прочитай первую ошибку в консоли и проверь указанную строку/имя функции.
    3. 

  3. Убедись, что все файлы, которые импортируются, существуют, а имя функции действительно объявлено в модуле.
    4. 

  4. Для невидимого спрайта проверь имя PNG, совпадение имени в sprite() и наличие файла в списке спрайтов.
    5. 

  5. Для невидимого объекта сцены проверь его имя в object("...") и то, что объект существует на вкладке «Сцена».
    6. 

  6. Если код синтаксически корректен, но игра ведёт себя не так, временно добавь print(...) и проверь значения переменных.
    7. 



Валидатор и проверка ресурсов находят часть проблем заранее, но не доказывают, что игра работает правильно во время выполнения.






21ИИ-агент: безопасный рабочий процесс


Открой «🤖 ИИ», затем «⚙ Подключение». Укажи Base URL совместимого API, API-ключ и имя модели; нажми «Сохранить». Адрес должен быть базовым адресом API без пути /chat/completions. Провайдер должен разрешать запросы из браузера (CORS).


Формулируй запрос с конкретной целью и ограничениями: жанр игры, управление касаниями, графика, условия победы/поражения, какие файлы можно менять. Например: «Добавь счёт монет, не меняй управление и сохрани имя главного спрайта hero».


Агент может учитывать код файлов, спрайты и объекты сцены; создавать или менять файлы и сцену; подсказывать, какие PNG импортировать. Он не генерирует изображения сам. После применения результата обязательно запусти игру, посмотри консоль и проверь результат глазами.


Приватность: API-ключ хранится в локальном хранилище браузера и отправляется напрямую выбранному провайдеру. Не используй ключ, который не имеешь права применять; не вставляй в запросы пароли или другие секреты. Если не доверяешь провайдеру, не отправляй ему содержимое проекта.

24Размер экрана и наклон телефона


screenWidth() и screenHeight() возвращают размер видимой области браузера в CSS-пикселях — в том числе после перехода в полноэкранный режим. Это размеры окна устройства, а не координаты рисования. Игровые координаты по-прежнему фиксированы: gameWidth() возвращает 800, gameHeight() — 450. Используй последние для размещения объектов на сцене.


orientationAngle() сообщает угол поворота экрана, isPortrait() — вертикально ли расположено окно. tiltX() возвращает наклон влево/вправо (gamma), tiltY() — вперёд/назад (beta), tiltZ() — alpha. Это углы датчика, а не гарантированное направление на север.


На некоторых телефонах браузер требует разрешение на датчики. Вызывай requestMotion() в ответ на касание/нажатие пользователя. На неподдерживаемом устройстве или без разрешения углы могут оставаться нулевыми; датчики обычно требуют HTTPS или localhost.


function pointerDown(x, y) {
    requestMotion(); // запросить разрешение после касания
}
function update(dt) {
    clear("#101827");
    let x = gameWidth() / 2 + tiltX() * 3;
    let y = gameHeight() / 2 + tiltY() * 2;
    circle(clamp(x, 20, gameWidth() - 20),
           clamp(y, 20, gameHeight() - 20), 20, "#70d6ff");
    text("Окно: " + screenWidth() + "×" + screenHeight(), 16, 18, "#ffffff", 16);
    text("Наклон: " + round(tiltX()) + ", " + round(tiltY()), 16, 42, "#c5d2e8", 14);
}






25Деплой игры в интернет (GitHub Pages)


Деплой публикует собранную игру как сайт. В MrrCode Studio открой вкладку «Файлы» и нажми «Опубликовать на GitHub Pages». Инструмент собирает отдельный index.html из текущего проекта и отправляет его в репозиторий GitHub; исходный редактор в опубликованную игру не входит.


Шаг 1. Создай репозиторий


  1. Войди на github.com/new.
  2. Задай имя, например my-mrr-game, и создай репозиторий. Для простого деплоя можно выбрать Public.
  3. Запомни имя владельца GitHub, имя репозитория и ветку (обычно main).


Шаг 2. Создай токен с правом записи


  1. Открой Fine-grained personal access tokens и создай токен.
  2. В Repository access выбери Only select repositories и отметь только свой репозиторий.
  3. В Repository permissions найди Contents и выставь Read and write, затем создай токен и скопируй его.


Если пункта Contents нет: проверь, что создаёшь именно Fine-grained token, а не другой тип. Для Classic token эквивалентный старый вариант — scope repo (он даёт более широкие права). В организации создание токена может ограничиваться её политикой; тогда используй личный репозиторий или попроси владельца организации разрешить такой доступ. Не отправляй токен в чат и не публикуй его.


Шаг 3. Заполни окно публикации


  1. В поле Владелец укажи имя пользователя/организации GitHub.
  2. В Репозиторий — имя репозитория без URL.
  3. В Ветка — main (или выбранную ветку).
  4. Вставь токен в поле пароля и нажми «Собрать и опубликовать». Токен нужен только для запроса к GitHub; закрой окно после публикации, чтобы очистить поле.


Шаг 4. Включи GitHub Pages


  1. Открой репозиторий на GitHub → Settings → Pages.
  2. В разделе сборки выбери Deploy from a branch, ветку, которую указал при публикации (обычно main) и папку /(root), затем сохрани. Если этот источник уже настроен, повторно менять его не нужно.
  3. Подожди несколько минут и обнови страницу Pages. GitHub покажет адрес сайта. Для обычного репозитория адрес обычно выглядит как https://ВЛАДЕЛЕЦ.github.io/ИМЯ-РЕПОЗИТОРИЯ/; для репозитория вида владелец.github.io адрес корневой.


После повторной публикации index.html обновится; Pages может потребовать несколько минут, чтобы показать новую версию. Если сайт выдаёт 404, проверь, что файл index.html находится в корне выбранной ветки и Pages настроен на эту ветку/папку. Ошибка 401 обычно означает неверный или истёкший токен; 403 — недостаточно прав; 404 в окне публикации может означать неправильное имя владельца/репозитория.


Важно: игра на GitHub Pages будет публичным сайтом, если репозиторий и настройки Pages допускают публичный доступ. Не добавляй секретные ключи API в код игры — всё, что включено в HTML, посетители могут прочитать. Если игра использует сохранение, оно хранится в браузере каждого игрока отдельно.
